# Ручной сбор: цены и прокат

Папка для данных, собранных руками. У каждого файла рядом лежит
мета-файл .meta.json с родословной цифр: источник, дата сбора, решения.

## prices_season_2026_27.csv - цены ски-пассов

Сезонный срез: одна строка на курорт, 29 из 32 с ценой. Файл подключен
в конвейер (витрина берет цены прямо отсюда), поэтому правки в нем
сразу влияют на рейтинг - после правок пересобрать витрину
(`python src/run_all.py`).

Колонки:
* adult_price_min_rub / adult_price_max_rub - признак рейтинга:
  минимальная разовая дневная цена (max может включать абонементы,
  в баллах не участвует)
* child_price_min_rub / child_price_max_rub - пусто = детского тарифа нет
* price_season - сезон, к которому относится цифра
* source_confidence - official_single_source / multiple_sources_lower_confidence /
  not_specified / not_collected
* collected_at - дата сбора/проверки (YYYY-MM-DD)
* price_note - родословная цифры: что проверено, откуда fallback,
  абонементные тарифы "только абонемент" курортов

Пустые цены = разовая цена не опубликована (только сезонные абонементы
или курорт не работает) - в рейтинге это нейтральный балл 50 и флаг
missing price.

## rental_schools_2026_27.csv - прокат, школы, инструкторы

Заготовка на будущее (расширение сверх ТЗ). Одна строка = одна услуга.
service_type из набора: ski_rental_standard / ski_rental_top /
snowboard_rental / school_group_lesson / school_private_lesson /
instructor. price_unit: за день / за час / за занятие.
В рейтинге не используется (услуга есть почти везде - признак
не различает курорты); файл - пустой шаблон, resort_id и названия
уже вписаны.

## Правила

* Оригинальные файлы стартового пакета не редактировать - только свои.
* Одну дату проверки на файл (как в resort_checks).
* Пусто = "нет услуги/тарифа", это честная пустота; лучше пусто,
  чем скопированное с чужого сайта.
